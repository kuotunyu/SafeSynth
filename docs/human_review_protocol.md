# SafeSynth 人工框選審核規範

本文件是所有人工審核頁面的共同規則。若審核頁沒有完整顯示本規則，
該次審核不得用來開啟正式生成閘門。

## 目標類別

本專案採用 `class_direct`：

- `helmet` 表示「**戴著安全帽的頭部區域**」，不是所有實體安全帽。
- 每一位戴著安全帽的人各有一個 `helmet` 框。
- 框通常包含安全帽、頭部及部分臉部；不得擴張到上半身或整個人。
- 同一個人若戴著安全帽，就不再另外標 `head`。
- `head` 表示沒有戴安全帽的裸頭。

## 不應標成 `helmet`

以下物件即使外觀像安全帽，也不應有 `helmet` 框：

- 放在地上、桌上、車上或被手拿著，沒有戴在人頭上的安全帽；
- Logo、海報、浮水印、倒影或背景圖樣；
- 普通人臉或裸頭；
- 黃色機具、圓形物體及其他 helmet-like hard negatives。

孤立、未穿戴的安全帽是刻意保留的負樣本；它只用來降低誤報。

## 人工審核分類

每個案例只使用下列分類：

1. `PASS`
   - 每個清楚可見的戴帽頭部各有一個合理的模型框；
   - 孤立安全帽與其他負樣本沒有模型框。
2. `MODEL_FALSE_POSITIVE`
   - 洋紅框內沒有戴著安全帽的頭部。
3. `MODEL_MISS`
   - 有清楚可見、確實戴著安全帽的人頭，但沒有任何合理洋紅框。
4. `MODEL_LOCALIZATION`
   - 框只覆蓋戴帽頭部的一小部分、明顯包含過多身體，或一框合併多人。
5. `DATASET_GT_DEFECT`
   - 綠框標到非戴帽頭部，或清楚的戴帽頭部缺少綠框。
6. `UNCERTAIN`
   - 太小、嚴重遮擋或畫質不足，無法確定安全帽是否戴在人頭上。

`UNCERTAIN` 不得直接算成模型錯誤或模型正確。案例必須隔離，並依照預先
凍結的替補順序換入新案例。

## 兩階段驗收

為避免模型輸出影響人工對資料標註的判斷，新的正式驗收分成兩階段：

1. **GT-only adjudication**
   - 只顯示原圖與綠框，不顯示模型框；
   - 先確認每一個框都遵守本文件，並隔離資料缺陷與不確定案例。
2. **Model review**
   - GT 集合凍結後才顯示模型洋紅框與 overlay；
   - 只有模型錯誤為零，才能通過人工閘門。

替補樣本、抽樣種子、來源群組排除與最終案例數，都必須在顯示任何模型輸出
之前凍結。Validation 與 Test 不得用於這兩階段。

## 審核頁面最低說明

每一頁都必須用中文顯示：

> 目標是「戴著安全帽的頭部」。一人一框，框可含安全帽＋頭／部分臉。
> 孤立、未穿戴的安全帽不要框。綠＝資料 GT，洋紅＝模型。

頁面也必須顯示 `PASS / FP / MISS / LOCALIZATION / GT DEFECT / UNCERTAIN`
六種可回報分類。未顯示上述說明的頁面只能作為探索性診斷，不能作為正式驗收。
